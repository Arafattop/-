# АгроМаркет API

REST API на Node.js + Express + PostgreSQL.

## Запуск

1. Установить PostgreSQL, создать базу `agromarket`
2. Скопировать `.env.example` в `.env` и указать свой пароль
3. `npm install`
4. `npm run db:init` — создать таблицы и загрузить товары
5. `npm run dev` — http://localhost:3000

## Эндпоинты

| Метод  | Путь                | Описание                                         | Ответы        |
|--------|---------------------|--------------------------------------------------|---------------|
| GET    | /api/health         | сервер и связь с БД                              | 200           |
| GET    | /api/about          | информация об API                                | 200           |
| GET    | /api/products       | товары: `?search=`, `?sort=price`/`-price`, `?limit=`, `?offset=` | 200 |
| GET    | /api/products/:id   | один товар                                       | 200, 400, 404 |
| POST   | /api/products       | создать товар                                    | 201, 400      |
| PUT    | /api/products/:id   | изменить товар                                   | 200, 400, 404 |
| DELETE | /api/products/:id   | удалить товар                                    | 204, 400, 404 |
| GET    | /api/orders         | заявки + название товара, `?status=`             | 200           |
| POST   | /api/orders         | новая заявка                                     | 201, 400      |
| PATCH  | /api/orders/:id     | сменить статус заявки                            | 200, 400, 404 |

Тесты: коллекция `postman/agromarket.postman_collection.json` (Postman → Import → Run).

## Лабораторная 6 — ответы

> Ответы ниже — ожидаемые результаты, выведенные из схемы и кода. Тексты ошибок PostgreSQL

**Часть 2. SQL вручную**
- Самый дорогой товар: `SELECT * FROM products ORDER BY price DESC LIMIT 1;` (в данных — «Мёд цветочный», 3200).
- `INSERT ... price = -5` → ошибка `new row for relation "products" violates check constraint "products_price_check"` — сработал `CHECK (price >= 0)` (код 23514).
- `INSERT` без name → `null value in column "name" of relation "products" violates not-null constraint` — сработал `NOT NULL` (код 23502).
- Заявка с `product_id = 9999` → `insert or update on table "orders" violates foreign key constraint "orders_product_id_fkey"` — сработал внешний ключ (код 23503).

**Часть 3. SQL-инъекция**
- Небезопасный запрос с `search = zzz' OR 1=1 --` вернул **все товары** (столько, сколько их в таблице), хотя «zzz» нет ни в одном названии: условие `OR 1=1` всегда истинно, а остаток запроса стал комментарием.
- С одной кавычкой `'` небезопасный запрос ломается: получается незакрытая строка, база отвечает синтаксической ошибкой, сервер — статусом **500**, в терминале виден текст ошибки SQL.
- После возврата параметризованного варианта (`$1`) оба адреса дают `200` и пустой массив `[]`: значение целиком воспринимается как данные — искомый текст «zzz' OR 1=1 --», такого названия нет.

**Часть 4. CRUD в Postman**
- POST создаёт товар: статус **201**, в ответе новый `id` (его выдал SERIAL); после обновления страницы товар виден в каталоге React.
- PUT на `/api/products/<id>` → **200**, GET показывает новое название и цену.
- POST с `"price": -5` и POST без `name` → **400** с текстами «Поле price должно быть целым числом ≥ 0» и «Поле name обязательно».
- DELETE → **204**; повторный DELETE → **404** «Товар не найден».

**Часть 6. Заявки**
- После перезапуска сервера заявка на месте: данные хранятся в таблице `orders`, а не в массиве в памяти.
- Заявка с `product_id: 1` в `/api/orders` содержит `product_name` (его даёт LEFT JOIN).
- Заявка с `product_id: 9999` → **400** «Связанная запись не найдена»: ответ сформировал `errorHandler` из ошибки внешнего ключа (код 23503) от базы.
- «Двойная защита»: при отключённой JS-проверке и `quantity: 5` приходит **400** «Значение не проходит проверку в БД» — заявку не пустил `CHECK (quantity >= 10)` (23514). JS-проверка всё равно нужна: она даёт понятное сообщение («Минимальный объём заказа — 10 кг») и не гоняет заведомо плохой запрос в базу, а CHECK — последняя линия защиты, если данные придут в обход API.
- После удаления товара заявка остаётся, а её `product_id` становится `NULL` (`ON DELETE SET NULL`), `product_name` — `null`.
